# L1 - High-Level Requirements

**System:** Primer — a .NET command-line tool that generates contextual agent instruction files for a repository and verifies that required Model Context Protocol (MCP) components are installed.

**Scope note:** Primer is a terminal application, not a web application. The standard responsive-viewport requirements (XS–XL breakpoints) do not apply; their equivalent for this system is terminal-surface adaptability — output must remain legible and complete across terminal widths, colour capabilities, encodings, and interactive/non-interactive contexts. That concern is captured in L1-014.

---

## L1-001: Installable .NET tool distribution
The system must be packaged and distributed as an installable .NET tool that can be installed globally or locally from a NuGet package and invoked by a stable command name from any working directory.

## L1-002: Command-line interface surface
The system must expose its capabilities through a discoverable command-line interface built on `System.CommandLine`, with self-documenting help, a stable option vocabulary shared across commands, and a documented exit-code contract that automation can depend on.

## L1-003: Repository context discovery
The system must inspect the target repository and derive the factual context an agent needs — repository root, technology stack, build/test/lint invocations, project layout, and existing engineering conventions — without executing any of the repository's own code or build tooling.

## L1-004: AGENTS.md generation
The system must generate an `AGENTS.md` file containing repository-specific guidance for coding agents, structured and constrained according to established AGENTS.md authoring practice, and grounded only in facts derived from the repository under analysis.

## L1-005: Multi-agent tool support
The system must support multiple coding-agent tools and modes — including Codex, Gemini, Claude, and Copilot — writing each tool's conventional instruction file to its conventional location, with `CLAUDE.md` and every other tool-specific file linking to `AGENTS.md` as the single source of truth rather than duplicating its contents.

## L1-006: Safe, idempotent, reviewable file generation
The system must never destroy work a human has authored. All file generation must be previewable before it happens, idempotent when repeated, confined to a clearly delimited managed region when a file already exists, and verifiable after the fact so drift between the repository and its generated agent files can be detected.

## L1-007: MCP component verification and remediation
The system must determine which MCP servers a repository requires, detect which of those are already installed in the developer's agent clients, report the gap, and — only with explicit operator consent — install or repair the missing components.

## L1-008: Configuration, options, and customisation
The system must be configurable through the standard Microsoft.Extensions configuration, options, and dependency-injection patterns, with a documented precedence order across defaults, configuration files, environment variables, and command-line arguments, and must allow teams to override the generated content templates.

## L1-009: Architecture and maintainability constraints
The codebase must be organised as vertical feature slices under `src/` with tests under `tests/`, follow the one-file-per-command pattern, apply SOLID principles, and enforce these constraints mechanically rather than by convention alone.

## L1-010: Acceptance-test-driven development and traceability
Every behaviour the system exhibits must originate from an acceptance criterion expressed in Given–When–Then form, be covered by an integration test written before the implementation, and be traceable in both directions between requirement and test.

## L1-011: Security and safe operation
The system must treat the repository it analyses, the network, and the developer's machine as untrusted boundaries: it must not leak secrets into generated files or logs, must not write outside the target repository, must not execute repository-supplied or remotely-fetched code, and must not silently modify developer configuration.

## L1-012: Performance and resource efficiency
The system must start fast, complete its work within predictable time bounds on repositories of realistic size, and bound its memory and file-handle consumption regardless of repository size.

## L1-013: Observability, diagnostics, and error handling
The system must produce structured, level-controlled diagnostic output on the correct stream, fail with actionable messages rather than raw stack traces, and offer a stable machine-readable output format for use in scripts and CI.

## L1-014: Terminal presentation and environment adaptability
The system's output must remain complete and legible across terminal widths, colour and Unicode capabilities, and interactive versus redirected/CI contexts, and must never require interactive input in a non-interactive session.
